# TeamWork 项目价值汇报

> **依据**：[README.md](../README.md)（@teamwork/cli v1.0.14）与 [demo-collaboration.md](./demo-collaboration.md)（Leader × 成员双端真实协作演示剧本，全部机制为已实现系统行为）。
> **演示场景**：登录重构组（ws-login）——Leader 阿哲 + 前端成员小雨，在各自 AI 工具（TRAE / Claude Code / Cursor / 任意 MCP 宿主）中完成「JWT 中间件 + 登录页 UI + API 联调」三个任务的全流程协作，全程约 70 分钟（T+0:00 发布 → T+1:10 整链闭合）。

---

## 一、项目定位：给现有 AI 开发补上"协作层"

TeamWork 是一个**多用户 AI 协作系统**：它不替换任何人的 AI 工具，而是让多人在各自的 TRAE / Claude Code / Cursor / 任意 MCP 宿主里，像同一条流水线一样协作——**任务发布 → 画像感知拆分 → 抢锁拾取 → 并行开发 → 记忆跨人流动 → 依赖自动解锁 → 跨人继承联调**。

它针对的是现有 AI 开发的三类隐性成本（演示剧本通篇在消除它们）：

| 隐性成本 | 现状（无 TeamWork） | 演示中的证据 |
|---|---|---|
| **上下文税**：AI 会话是天然孤岛，每个人的 AI 不知道别人做了什么 | 给队友的 AI 交代背景，需要人工粘贴提示词——演示明确指出后继者本需手动走「search → timeline → get_observations → 开发 → report_done」5 步提示词流程 | 小雨拾取 T-2/T-3 时，任务描述、验收标准、共识、gotcha、前人摘要全部由 ContextBundle 自动注入（2K 预算） |
| **试错税**：AI 无跨人记忆 | 一个人踩过的坑，另一个人的 AI 原样再踩一遍；命名/架构规范不一致，到联调阶段才暴露返工 | 小雨 T+0:25 踩 CSS 定位坑 → gotcha 置顶注入；阿哲 T+0:35 提命名共识 → Δ 增量注入全员，避免"后面联调要打架" |
| **协调税**：任务分配、进度同步、背景交接全靠喊话 | Leader 需了解每个人技能再手动派活；群里互问"你做到哪了"；交接靠口头 briefing | 画像感知拆分自动定向分发；observe 静默入图，双方看节点地图即知进度，**全程零会议、零进度汇报** |

演示结语点出的三个「零输入」时刻，就是这套系统对三类税的系统性消除：

1. **发现任务零输入**——SessionStart hook 静默注入收件箱候选，Leader 无需喊话分配；
2. **同步进度零输入**——observe 钩子自动上报入图，队友无需问「你做到哪了」；
3. **继承背景零输入**——后继任务拾取者拿到前人全部记忆注入，无需粘贴任何背景提示词。

## 二、价值维度一：效率提升（演示时间轴逐项对照）

演示中一次「3 任务登录重构」的双人协作在 **70 分钟内闭合**，且不含任何会议、进度汇报与任务交接文档。逐项对照：

### 2.1 任务拆分与分配：一句话 → 画像感知定向分发

- **传统做法**：Leader 需掌握每个成员的技能栈，手动拆任务、逐个写任务描述与验收标准，再逐人沟通认领。
- **演示呈现**（幕 1，T+0:00）：Leader 一句自然语言「把登录模块重构拆一下发下去，我负责 JWT 中间件，小雨擅长前端，页面给她做，最后留一个联调任务」→ `teamwork_publish_task` 不带 subtasks → 服务器 `splitTaskWithAI` 读取成员档案（小雨 shareSkill=[前端/CSS] + 空闲状态 ✓）→ T-2 定向注入她的收件箱，T-1 默认 Leader 自留，T-3 自动挂 `dependsOn=[T-1, T-2]`。
- **节省**：任务分析、画像匹配、任务描述撰写、验收标准传递——全部由服务器代劳，且任务树拓扑（依赖关系）同时建立。

### 2.2 开工背景：零提示词拾取（ContextBundle）

- **传统做法**：拾取者要向自己的 AI 粘贴背景：需求是什么、做到什么程度、有什么规范、前置依赖谁在做。
- **演示呈现**（幕 2，T+0:03）：小雨只说「看到收件箱有登录页任务，我来做这个」→ `teamwork_ack` CAS 原子抢锁后，ContextBundle（R1 白名单 + 2K 预算）自动注入：任务描述 + 验收标准、gotcha 置顶区、共识层 v0 + Δ 增量、拓扑行（T-1 是 T-3 的依赖，Leader 认领中）。她的 AI 从此刻已"知道要做什么、做到什么程度、有什么规范"。
- **节省**：背景提示词的撰写与粘贴环节整段消失；CAS 抢锁同时根除了"两人做到同一个任务"的重复劳动风险。

### 2.3 并行开发与进度可见：互不阻塞 + 节点地图实时长节点

- **传统做法**：要么串行等待，要么群里互问进度；Leader 想掌握全局只能开会或逐个问。
- **演示呈现**（幕 3，T+0:10 ~ T+0:40）：双端**同时**开发（阿哲写 `server/middleware/auth.js`，小雨写 `views/login.vue`），observe-hook 静默上报双方产出 → 经隐私管线（`<private>` 剥离 + 正则脱敏，密钥实测拦截）→ AI 总结为 FlowNode 入图 → 飞书云同步 + SSE 推送——**对方的仪表盘节点地图实时长出新节点**，期间所有 ack/observe/share/report_done 持续刷新租约保活。
- **节省**：进度同步的沟通成本归零；且因进度可见，联调时机判断（T-2 完成即可启动 T-3）无需额外协调。

### 2.4 依赖与解锁：完成上报自动驱动下游

- **传统做法**：上游完成后需要人通知下游"可以开始了"，并口头交代注意事项。
- **演示呈现**（幕 6，T+0:40 起）：阿哲 `report_done`（Stop 摘要式三段结构：completed / learned / next_steps）→ 服务器完成解锁检查（T-3 依赖 = T-1✅ T-2❌ → 尚不解锁）；5 分钟后小雨 T-2 完成 → 依赖全满足 → **T-3 自动进收件箱 + 默式注入**，小雨下个会话 SessionStart 即看到，直接 `ack` 开工联调。
- **节省**：上下游交接的等待与通知环节消失，任务链自动流转。

### 2.5 时间轴总览（演示原文）

```
阿哲 ██████ T-1 开发 ██████┤ done ─┄┄┄┄┄┄┄（等 T-2）┄┄┐
                                                ├─→ T-3 联调（小雨）████ done
小雨 ──┤ T-2 开发 ██████████████████┤ done ──────┘
       ▲                        ▲
  ack 抢锁(T+0:03)     gotcha 分享(T+0:25)——阿哲端节点地图实时可见
       ├────── 双方 observe 静默上报持续整个开发期，互不阻塞 ──────┤
```

**结论**：效率提升的本质不是"写得更快"，而是**把人与人、AI 与 AI 之间的等待、粘贴、询问、通知四类协作开销压缩到接近零**——这些开销在多人 AI 开发中本会随人数超线性增长。

## 三、价值维度二：减少试错流程（四道防线）

单人 AI 开发的试错，源于"AI 不继承别人的经验"。TeamWork 让经验随任务链结构化流动：

### 3.1 gotcha 跨人流动——同一个坑，全组只踩一次（演示幕 4）

小雨 T+0:25 发现「表单徽章全飞到弹窗右上角叠一起」→ 定位为全局 CSS 的 absolute 角标样式泄漏 → 修复后 `teamwork_share_memory(type=gotcha)` 沉淀为 gotcha 节点并 **R8 置顶**。此后**任何成员 ack 后继任务时此 gotcha 自动置顶注入**——演示明确注明「T-3 联调者将直接避开这个坑」。
- **传统代价**：另一个人的 AI 大概率重复调试同一类 CSS 问题；gotcha 机制把它压缩为"开工前一行警告"。

### 3.2 共识 Δ 注入——规范冲突在源头拦截（演示幕 5）

阿哲 T+0:35 提议共识「组件名 PascalCase，函数用 camelCase」→ 版本化 v0→v1 待确认 → 小雨端下一次任意 MCP 调用的返回 Bundle 尾部自动出现 Δ 增量提示 → `confirmId` 确认 → **注入全员上下文（LSTM 长线记忆）** + 飞书 consensus-snapshot 版本化快照。
- **传统代价**：阿哲原话即答案——「不然后面联调要打架」：规范不一致到联调/评审阶段才暴露，返工的是已写完的代码。三道闸（confirmed ≤20 条 / 单条 ≤60 字 / 48h 超时转裁决）保证共识层轻量不膨胀。

### 3.3 RNN 注入边——联调任务自带前人"避坑指南"（演示幕 6）

小雨 ack T-3 时的 ContextBundle 含：
- 📌 **阿哲 T-1 的完成摘要**：「learned: 飞书 token 2h 过期需续期 / next_steps: 联调时注意 role 字段」——上游开发者主动预埋给下游的试错警告；
- ⚠️ **幕 4 的 gotcha 置顶**（CSS 坑）；
- **共识 v1 全文** + 她自己 T-2 链上最近 10 条记忆（renderTaskChain 依赖闭包）。
- **传统代价**：这些信息零散在两人的聊天记录和记忆里；联调者要么重新踩一遍（token 过期、role 字段对不上），要么专门约一次交接会。

### 3.4 崩溃回退与失败记忆——走过的死路不必再走

开发链崩溃时 `teamwork_revert` 软删回继承点，**崩溃原因自动沉淀为失败记忆，重新开发时自动注入**，避免重蹈覆辙；且带 reorg 防护（链被下游引用时拒绝回退），防止试错本身引发新的连锁错误。

### 3.5 检索兜底：先问再做，而非重造

三层渐进披露（search 索引 ~50 tokens/条 → timeline 上下文 → get_observations 详情）让 AI 在写代码前能低成本查到"组里有没有人做过类似实现"——完整三层工作流约 3K tokens 即可拿到 100% 相关上下文，远低于盲目重写或整段粘贴历史的开销。

## 四、价值维度三：落地价值（为什么可以直接用）

1. **零换工具成本，异构 AI 混编**：成员各用各的 TRAE / Claude Code / Cursor，协作经 MCP + 注入文件完成——不需要团队统一 AI 工具，不存在迁移阵痛。
2. **成员接入约 5 分钟、真零安装**：`teamwork setup` 自动检测本机 AI 工具并写入 MCP 配置；成员加入工作组只需名称 + 密码（Wpassword），打开 AI 工具即可开始协作（README 四步流程：启动 → 注册 → 创建/加入工作组 → setup）。
3. **团队产出从"聊天记录"升级为"资产"**：
   - 全部工作产出自动沉淀为团队记忆（FlowNode 节点图：When·Who·What 四维快照，含 role/topoPath/consensusVer/injectedFrom）；
   - **飞书云同步**——换机、新成员加入即自动恢复全部任务/记忆；
   - 未完成开发链可被新成员**自主继承**（open-ends 列表 → inherit 抢锁 → InheritBundle 含链上节点 + 域内记忆 + 共识 + 拓扑）——人员流动不再导致项目知识断层；
   - 数据全部落本机 `~/.teamwork/`，升级安装包不丢数据。
4. **协作治理产品化**：租约产出保活（心跳不算、ack/observe/share/report_done 四类产出刷新，超时自动回收任务）、任务看板、成员三态、共识管理（确认/裁决/归档）、节点地图可视化——"谁在干什么、卡在哪"从口头状态变为可审计数据。
5. **实施成熟度（实测状态，2026-10-12）**：server/mcp 侧已完成并实测——协作域 19/19 冒烟通过 + HTTP 全链路（含 ack CAS 抢锁、依赖门控与解锁、评分排序）；MCP 工具面收敛、每次调用 <1s 返回；v1.0.14 提供三种分发方式（npm 在线 / .tgz 离线 / .zip 零依赖），适配无外网内网环境。
6. **适用场景**：2~10 人小团队的功能开发、模块重构、跨前后端联调、新成员快速上手、需要留痕与交接的长期项目。腾讯会议式多工作组模式（每人可自建组当 Leader、同时是其他组成员）支持跨团队复用。

## 五、花费什么成本

### 5.1 部署成本（一次性，低）

| 项 | 内容 |
|---|---|
| 环境 | Node.js >= 18（本机 server + 仪表盘形态：每人跑一个 server，飞书云文档 `NodeMap.md` 为唯一共享层） |
| 安装 | `npm install -g <包路径>.tgz`（另有 .zip 零依赖包）；`teamwork start` 即启动并打开仪表盘 |
| 成员接入 | `teamwork setup` 一键配置 AI 工具 MCP（约 5 分钟四步）；可选 `teamwork feishu-auth` 绑定个人飞书身份 |
| 运维 | `teamwork doctor` 环境自检（Node/凭据链/飞书连通性）；升级三步 `stop → install → start`，数据不丢 |

### 5.2 人的使用成本（持续，几乎为零）

- **人只说自然语言**：演示中全部人机交互就是日常话术——「把登录模块重构拆一下发下去」「看到收件箱有登录页任务，我来做这个」「表单徽章怎么全飞到弹窗右上角叠一起了?!」「中间件好了，上报完成」。
- **不需要记工具**：MCP 工具（inbox_status / ack / report_done / share_memory / consensus…）由 AI 按协议自动调用；hook 链路（SessionStart / observe）**零提示词静默**。
- **学习成本主要在 Leader**：发布任务、确认/裁决共识、管理成员——均为仪表盘点击操作。

### 5.3 AI Token 成本（持续，可控）

| 消耗点 | 说明 | 控制手段（已内建） |
|---|---|---|
| 任务拆分 | 发布时 `splitTaskWithAI` 调 Leader 配置的 AI | 仅发布时触发 |
| observe 总结 | 开发期对话产出经成员自配 AI 总结为 FlowNode | 摘要类任务可用廉价模型（如 claude-haiku 级）；多密钥池 + 配额回退可选 |
| 上下文注入 | ContextBundle / inject 文件 | **2K 预算硬裁剪（R7）**、L0 索引 ~50 tokens/条、渐进披露（先摘要后详情）、共识层 ≤20 条且单条 ≤60 字 |
| 检索 | 三层 search/timeline/get_observations | 按需加载，完整链路约 3K tokens |

每个成员自带 AI Provider（Base URL / API Key / Model ID，仅存本地），成本随成员各自结算；仪表盘含 Metering（token 用量可查 + 预算告警）。

### 5.4 治理与风险成本

- **治理**：Leader 分发工作组密码、裁决冲突共识条目；隐私管线自动脱敏（`<private>` 剥离 + 正则），但成员需对敏感内容保持标注习惯。
- **已知风险与既定对策**：会话 token 泄漏可冒充成员（可吊销/轮换/绑机器指纹）；TRAE 版本迭代可能变动 rules/MCP 机制（冒烟脚本 + 适配器隔离层应对）；Leader 单点已转化为设计特性（便携模式：休眠即暂存资产落飞书、重开即恢复 + WAL 式 CHECKPOINT 兜底）。
- **外部依赖**：飞书开放平台应用 + 管理员将成员加入可用范围（个人身份绑定为可选项）。

## 六、投入产出总览

| 协作动作 | 传统做法 | TeamWork 做法 | 被消除的开销 |
|---|---|---|---|
| 任务拆分/分配 | Leader 手动拆 + 逐人沟通 | 一句话发布 → 画像感知定向注入 | 拆分分析 + 任务描述撰写 + 分配沟通 |
| 开工背景 | 人工粘贴背景提示词（5 步流程） | ContextBundle 自动注入，零输入 | 背景提示词全流程 |
| 进度同步 | 群聊互问 / 站会 | observe 静默入图，节点地图实时可见 | 进度沟通（整段） |
| 防重复劳动 | 口头认领，可能撞车 | CAS 原子抢锁 | 并发冲突 |
| 踩坑成本 | 每人各自踩一遍 | gotcha 置顶注入，全组只踩一次 | 重复调试时间 |
| 规范一致性 | 联调期发现冲突再返工 | 共识 Δ 实时注入全员 | 集成期返工 |
| 上下游交接 | 通知 + 口头交代注意事项 | report_done 自动解锁 + 摘要注入下游 | 交接等待与 briefing |
| 新人/换机接手 | 长期背景 briefing | 飞书云自动恢复 + 链路继承 | 交接与入职成本 |

**一句话概括 ROI**：一次性付出约 5 分钟接入 + 少量 AI 摘要 token 的成本，换取多人 AI 开发中**协调、交接、重复试错三类开销的持续压缩**；且团队记忆随使用自动增值（每次协作都在为飞书云资产库积累），人员流动不再冲销既有积累。

## 七、边界与假设

1. 演示为 2 人场景（设计本身支持多工作组、多成员，腾讯会议模式）；
2. Token 成本取决于各自配置的 AI Provider 定价与协作频率，非固定值；
3. 飞书同步依赖开放平台应用与管理员配置可用范围；
4. 宿主能力有档差：TRAE 无生命周期钩子时退化为"任务级观察"（协作节点自动、工具级观察缺失），Claude Code 等钩子宿主可升级"完全态"——但发布→注入→拾取→上报→解锁的核心闭环在全部宿主可走通。

---

## 八、结论

对现有 AI 开发而言，TeamWork 的价值不是"让 AI 写代码更快"，而是**把"N 个人 × N 个 AI 会话"从互不知情的孤岛，变成有共享记忆、有共识约束、有任务拓扑的流水线**：

- **效率提升**：等待、粘贴、询问三类协作开销在演示中全部归零——70 分钟完成含联调的 3 任务双端协作，全程零会议零汇报；
- **减少试错**：gotcha 置顶、共识 Δ 注入、RNN 注入边、revert 失败记忆四道防线，让个人经验变成组级免疫；
- **落地价值**：不换工具、约 5 分钟接入、实测闭环（M0 19/19 冒烟 + HTTP 全链路）、三种分发方式适配内网、数据本地 + 飞书云双保险；
- **成本构成**：部署一次性且轻；人的持续成本≈零（自然语言 + 零提示词）；AI 成本集中在廉价的摘要/拆分调用，且有 2K 预算、渐进披露、Metering 告警三重闸门。

> **适用判断**：只要团队满足「≥2 人在用 AI 写代码 + 存在任务并行与交接」，TeamWork 即有正向 ROI；人数越多、人员流动越频繁，记忆资产化的复利越明显。
